## 2. 已确认的建模事实与两条边界

### 2.1 Note Value 是瀑布的唯一主驱动（招股书原文已核对）

用 `member_B/tools/pdf_text.py` 从 `raw/prospectus.pdf` 取到的原文：

- *"The note value of the receivables on any payment date is the present value of the unpaid scheduled
  payments on the receivables, discounted at 8.85%."*
- *"The aggregate amount of principal payable on the notes on each payment date will generally be equal to
  the reduction in the note value of the receivables during a collection period."*
- *"the **note value** as of any calculation date will be the present value of the scheduled and unpaid
  payments on the receivables discounted at 8.85%."*
- 违约应收款：在"被收回设备"或"成为 180 天应收款"两者较早发生之前，其计划回款**按未违约情形推算**；
  该时点之后，计入 Note Value 的金额改为**服务商估计的可变现价值**。
- 本金顺序：A-1 → A-2A/A-2B 按比例 → A-3 → A-4；本金短缺可结转（`principal carryover shortfall`）。
- 服务费 1.00%/年，合同基数为**期初池余额**；招股书 65–66 页的收益率演示表则按 Note Value 计。

**模型含义**：只要在任一月份能给出"剩余应收款的未付计划回款"，Note Value 与票据本金分配同时确定。
这是本项目"汇总池模型"在方法上真正站得住的地方。

### 2.2 边界一：现金与池余额无法逐月闭合

用已披露的汇总字段反解每月隐含的池利息（年化）：

| 假设 | 隐含年化利率 vs 披露加权 APR，均值绝对误差 | 最大偏差 |
|---|---:|---:|
| 池余额下降额 = 已收本金 | 1.63 pp | 3.92 pp |
| 池余额下降额 + 行政回购 = 已收本金 | 2.64 pp | 7.43 pp |
| 池余额下降额 − 净损失 = 已收本金 | **1.36 pp** | 3.76 pp |
| 池余额下降额 + 回购 − 净损失 = 已收本金 | 2.24 pp | 7.37 pp |

`Total cash receipts` 与"池余额下降 + 净损失"之间不存在可用的一阶恒等式（局部月份反号）。
结构原因：99.3 不披露"本金回收 / 利息回收"的分项；`prepayment` 的定义在 Sale and Servicing
Agreement 而非招股书（招股书全文检索无此定义）；且 `prepayment` 有 7 个月为负。

**处置（写进模型限制，不在模型里强行对账）**：

- 历史校验**不**以"现金"为对象，而用 **Note Value 序列 + 池余额序列 + 分档本金序列**，
  这三条都能由计划回款结构直接推出（§4.3 已验证）。
- 现金侧只保留**结构恒等式**（§1.2 已 29/29 通过）：可分配额 = 四个来源之和；
  且 = 行政费 + 票据利息 + 票据本金 + 服务费 + 储备补足 + 受托人费 + 审查费 + 证书分配。
- 预测期现金由模型内生，因此现金侧天然自洽；代价是**不能**声称复现了服务商的现金对账。
  报告第 3 节必须原样写出这一段。

### 2.3 边界二：计划回款表只能定出一个收益率，不能定出"当前截面"的收益率

计划回款表与哪个本金口径配对，决定了隐含收益率（`solve_pool_yield` 的实测输出）：

| 配对的本金口径 | 隐含收益率 | 与披露加权 APR 4.745% 的差 |
|---|---:|---:|
| 期初本金，**不含**应计利息 1,670,001,216.47 | **5.5238%** | +78 bp |
| 期初余额，**含**应计利息 1,694,001,151.31 | **4.8240%**（季节拆分后 5.0236%） | **+8 bp**（季节拆分后 +28 bp） |
| 初始 Note Value 1,562,473,742.82 | 8.8500% | 恒等式的逆运算，不构成检验 |

**结论**：计划回款的"本金"成分包含那 24.0M 应计利息的偿还，而 99.3 第 12(a) 项的池余额不含应计利息。
所以 5.5238% 与 4.8240% 是同一张表的两种口径；含应计口径下与披露 APR 只差 8bp ——
**计划回款表是自洽的，不存在 16% 的数据矛盾**。
（这是对本计划第一版的修正：第一版把 5.5238% 当成"单一年金无法拟合计划表"的证据，实际是口径错配。）

**由此产生的约束**：这张表是"发行日"的无条件计划。摊到一个已存活 29 个月的截面上时，
剩余名义计划回款 746.3M 远大于存续余额 470.7M；直接对残表求收益率会得到 40%+ 的荒谬值。
所以**当前截面不能再用"计划表 + 收益率"直接摊销**，必须先把残表按存活状态缩放（§4.3）。

## 4. 模型设计

### 4.1 决策 D1：瀑布在 Note Value 空间驱动

- 主驱动：`principal_distributable_t = NV_start_t − NV_end_t + principal_shortfall_{t-1}`。
- 资金约束：`principal_paid_t = min(principal_distributable_t, 可分配现金 − 优先顺位支出)`；
  差额计入 `principal_shortfall` 并结转。历史上恒为 0，Base 情景也应维持 0。
- 分档：按 `principal_rank` 顺序全额清偿；A-2A/A-2B 同级按**原始本金比例**分配
  （A 的 `A2 pro rata per original dollar` 29/29 通过，B 必须复用同一规则，不按当前余额）。
- 利息：A-1/A-2B 用 ACT/360，其余 30/360（取 `Notes.day_count` 与 `days_*`）。
- 证书：`certificate_payment = 可分配额 − 上述全部顺位`（残余）。
- OC：**恒定 39,062,743**（29/29 已验证），因此 `票据余额 = NV − OC` 自动成立，无需 OC 触发逻辑。
- 储备：目标 = 初始 Note Value 的 1% = 15,624,737.43，29 期未动用。

### 4.2 决策 D2：最小状态——计划回款 + 一个收益率 + 存活状态

模型状态只有两个标量：存续余额 `B`、**已移除本金的累计现值** `V`。
外生（由计划表一次算定）：残表 8.85% 现值曲线 `PV_t`、无条件摊销路径 `B*_t` 与计划本金 `P*_t`。

```
NV_t        = PV_t − V_t                     # Note Value，永远由状态导出，不会漂移
ρ_t         = PV_t / B*_t                    # 每美元"无条件余额"对应的现值
removal_t   = prepay_t + loss_t + repurchase_t
V_{t+1}     = V_t + removal_t × ρ_t
B_{t+1}     = B_t − P*_t(本期间隔) − removal_t
```

**为什么用 ρ 加权，而不是 `NV = (B/B*) × PV`**：`B/B*` 是**余额**存活比，不是**现值**存活比。
被移除的多是久期偏短的贷款，其每美元现值比平均低；直接把余额比当现值比会系统性高估 Note Value 的降幅。
实测：余额比版本平均误差 −0.91%，ρ 加权版本 **−0.56%**（§4.3）。

**预测期的初始状态（截至 2026-11-16 付款后）**：

| 项 | 值 | 来源 |
|---|---:|---|
| `B` 存续余额 | 470,737,392.05 | 99.3 第 12(a) 项 |
| `NV` Note Value | 461,597,762.43 | 99.3 第 12(b) 项 |
| `PV_29` 残表 8.85% 现值 | 677,137,843.13 | 由计划表算定 |
| `V` = PV − NV | **215,540,080.70** | 反解，使模型与披露值同起点 |
| 剩余名义计划回款 | 746,274,020.88 | 计划表 2026-12 起 |

> 注意 `V` 必须由**披露的 NV** 反解（215.54M），而不是沿用历史回放累积出来的 218.01M；
> 否则情景的第一期就会带入 2.5M 的历史残差。

### 4.3 决策 D3：历史回放已验证（G3 通过）

用实际池余额路径驱动同一递推（移除额由余额变化反解，是数据不是假设），
逐月重建 29 个 Note Value：

| 指标 | 实测 | 门槛 |
|---|---:|---:|
| 平均绝对百分比误差 | **0.246%** | ≤ 0.40% |
| 最大绝对百分比误差 | **0.659%**（2025-05） | ≤ 0.90% |
| 期末（2026-11）误差 | **−0.024%** | ≤ 0.25% |
| 存活因子 `B/B*` | 1.0000 → 0.6706 | — |
| `ρ` | 0.9356 → 0.9647 | — |

**残差归因（三条，均已量化，不靠调参掩盖）**：

1. **应计利息口径**：余额隐含移除 227.84M，而 `prepayment + net_loss` = 225.49M，差 **+2.35M（1.0%）**；
   若再把 `repurchases`（32.05M）计入移除，则变成 −29.70M 的过大。说明**行政回购不应再作为额外的余额移除**
   （很可能已包含在 `prepayment` 口径内）。这一条已列为对 A 的问题 Q6。
   但月度层面仍有问题：隐含移除与 `prepayment` 的相关系数只有 **0.40**、平均月差 9.3M，
   季节性只把它从 9.70M 略降到 9.31M。**所以 A4（prepayment 的归集边界）依然是真问题**，
   季节性并没有解决它。
2. **提前还款的期限选择**：`ρ` 从 0.9356 升到 0.9647，说明被移除的贷款久期短于池平均。
   ρ 加权递推正是对这一现象的近似。
3. **损失滞后**：合同规定违约应收款在 180 天内仍按原计划回款计入 Note Value，
   而余额下降是即时的。损失仅占移除额 5.7%，故该项影响在 0.05pp 量级。

**映射口径的稳健性**：收款期是 Deere 财政周期（28–35 天），与日历月不对齐。
四种"已消耗计划月"的口径（月末早于收款起、月初早于收款起、`k+1` 经验式、月末不晚于收款起）
给出的平均误差分别为 0.588% / 0.561% / 0.574% / 0.583%（未加季节性时）—— **差异 ≤ 0.03pp，结论不依赖口径选择**。
加上季节性拆分后，四种口径的绝对水平整体下移约一半，排序不变。

**季节性拆分（B3）与它的代价**：池内 62.39% 的余额按年付，年付到期日集中在春播与秋收，
所以"利息按月平滑计提"是错的——高付款月的借款人一次付清全年利息。
`seasonal_weights` 从计划表本身反推 12 个月份的收款强度（去趋势后按月取均值、归一到均值 1），
得到 **1.25/1.31/1.49/1.28/0.43/0.62/0.72/0.91/0.89/1.16/0.74/1.21**（1–12 月），
即 3 月最高、5 月最低，与农机年付的季节性一致。

| 口径 | 隐含费率（不含应计） | 隐含费率（含应计） | G3 平均误差 |
|---|---:|---:|---:|
| 平滑计提 | 5.5238% | 4.8240% | 0.561% |
| **季节性拆分（采用）** | 5.7541% | 5.0236% | **0.246%** |

**代价必须说明**：季节性让 Note Value 的复现精度提高一倍，但让"含应计口径 vs 披露 APR"
的差从 8bp 扩大到 **28bp**。因为校准出的费率是一个**摊销因子**，不是池的合同 APR：
月份权重与余额水平的相关性会改变同一费率下的全年利息。
模型选择的判据是"能否复现 Note Value"（这才是模型存在的理由），
而 28bp 的差距量级上仍远小于任何情景差异。两个数字都写进 `calibration.csv`，不做取舍隐藏。
去趋势方法也做过稳健性检验：对数线性 0.246%、对数二次 0.232%、12 个月中心移动平均 0.284%，
**结论不依赖去趋势方式**。

**期间映射改用 Schedule C（A7）**：原先用"收款起点之前已开始的日历月数"作启发式；A 提供了 SA&S 的
Schedule C（财政月名与截止日），现已改为按 `collection_end` 与该表截止日精确联表。
有 5 个期间的索引因此改变（April 财政月截止在 5 月、October 截止在 11 月等），
但 G3 几乎不动（0.2461% → 0.2464%）——**这是为了口径可辩护，不是为了更准**。

按 A4 的要求做了前后移一期的对齐敏感性：

| 平移 | 平均 \|NV 误差\| |
|---|---:|
| −1 期 | 0.281% |
| **0 期（采用）** | **0.246%** |
| +1 期 | **3.691%** |

方向偏一期就崩到 3.7%，说明**数据把映射钉死了**，Schedule C 的对齐不是任意选择。
这同时是对 A4"相关系数 0.40 无法识别跨期原因"的正面回应：Note Value 本身能识别期次对齐，
只是 `prepayment` 的单月归属不可识别。

### 4.4 决策 D4：损失对 Note Value 的滞后

- 参数 `resolution_lag_months`（默认 6，敏感性 3/6/9）：违约金额在滞后结束时按
  `recovery_rate` 计入 Note Value，其余移除。
- 该参数直接改变 Severe 情景下尾部本金的**时点**，必须单列敏感性。
- 实现位置：`pool_model.advance` 的移除额拆分；回放阶段因移除额由余额反解，不涉及此参数。

### 4.5 决策 D5：提前还款口径与速度

`prepayment` 是服务商披露的**美元金额**，7 个月为负（合计 −30,995,477.85）。

- 负值最可能是"实际本金回收低于计划本金"（逾期），而非"提前还款为负"（待 A 确认，Q1）。
- 模型内**不直接用该字段作为速度**：
  - 历史回放：当作外生移除（§4.3 已如此），不做速度换算；
  - 预测：用 **CPR**，`SMM = 1 − (1 − CPR)^(1/12)`，作用于当期存续的计划本金；
  - 移除额 = `SMM × B_t`（当期存续余额），损失与回购按同样方式另计。
- Base 取值 **10% CPR**：历史双口径区间 6.2%–10.7%（正负相抵会低估真实再融资速度），
  敏感性给出 6% / 10% / 16% 三点。**16% 是发行人演示假设，必须标注**。

### 4.6 决策 D6：损失情景参数

- Base：以 0.79% 累计净损失 / 29 个月为锚，**由模型反解**年化 CDR，不预设数字。
- 损失率定义：**月度净损失 / 期初池余额**，年化后作为情景主轴（可加时间维度，便于 1.5×/2.0×）。
- 违约→损失：`recovery_rate`（设备抵押，默认 0.60，敏感性 0.4/0.6/0.8），
  回收进入现金流由 `recovery_lag_months`（默认 12）控制。

### 4.7 决策 D7：清仓赎回权（clean-up call）

- 触发：`NV ≤ 10% × 初始 Note Value = 156,247,374.28`。
- 按当前轨迹需累积约 273M 的 Note Value 下降，粗算落在 **2027 年末**附近（须由模型确认）。
- 届时合计票据余额约 117M（A-3 余额 25M 量级 + A-4 全额 91.7M），即**会把 A-4 提前清偿**；
  与发行人 16% CPR 下 A-4 的 WAL 3.58 年（≈2027-12）方向一致。
- 作为**显式开关**（默认"行使"），行使时一次性清偿剩余本金 + 应计利息，差额由证书持有人承担。
- A-3 法定最终付款日 2029-03-15 早于池最后一期计划回款 2030-05，
  说明结构上依赖"票据早于池期末清偿"；压力情景若把 A-3 拖过 2029-03，即构成
  真实的**法定到期风险**——这是报告第 6 节的核心结论之一。

### 4.8 决策 D8：A-2B 浮动利率与 SOFR 路径

- A-2B 已于 2026-03 清偿，只影响历史回放：必须用**实际** `a2b_rate`（A 已 29/29 校验）。
  预测期不需要 SOFR 路径。
- 若做"截至 2024-07 的全期限回顾"，需 SOFR 前向路径；届时以历史值外推并标注为模型参数。

### 4.9 决策 D9：IRR 的买入价必须明示

| 口径 | 价格 | 用途 |
|---|---|---|
| 一级市场 | `Notes.issue_price_per_100 / 100` | 与发行人 16% CPR WAL 同口径，历史实绩 |

   缓冲来自 OC 2.5% + 储备 1.0% + 超额利差，合计约 100M；票据敞口随摊还迅速缩小。
   到 24 倍时**证书现金被完全打光**（payout 0）、储备被全额提取 15.62M，A-3 仍全额兑付。
   **注意**：这一角格是"极端损失 + 零提前还款"的联合条件，报告应写成"尾部存在但需要极端联合条件"，
   不能写成"票据无风险"。
4. **速度压力对票据也只影响期限、不影响本金。** Moderate（8% CPR）与 Severe（6% CPR）的 WAL 只比 Base 长
   0.01–0.05 年，因为赎回权在损失把它推远之前就已经触发。

> **网格的可判定结论（不是"票据安全"）**：A-3 在整个被检验的损失×速度曲面内全额兑付；
> A-4 的尾部损失只在"无自愿提前还款 + 24 倍实现损失率"这一个角出现，金额 1,513,336（占其原始本金 1.65%）。
> 由于网格上限是 24 倍，**A-3 的破防点仍未被找到**——报告只能写"在被检验的范围内"，不能写"无风险"。

> **报告应据此调整叙事**：本项目最值得写的不是"压力如何伤害票据"，而是
> **"这个结构把全部损失压力都推给了证书，票据的真实风险是期限（赎回权），不是信用"**。
> 这与题目"损失与提前还款压力如何影响本金偿还、期限和回报"完全对得上，只是答案的方向和直觉相反。

### 6.3b 报告叙事决定（2026-11-28，用户定稿）

三情景压力测试**不降级**——它既是交付规格（项目计划 §4/§9），也是"损失被谁吃掉"这一结论赖以成立的证据。
真正的改动是**提问方式**：§5 从"压力有多大"改成"损失去了哪里"，§6 再把解释反转过来。两段式结构：

- **§5 用常规方法把证据摆完**：5.1 基准重建 → 5.2 三情景 × 行使/不行使 → 5.3 42 格曲面 + 损失吸收阶梯
  → 5.4 唯一尾部格。§5 开头放五行路线图，避免读者觉得被偷袭。
- **§6 谁承担什么**：6.1 票据期限由赎回权决定 → 6.2 赎回权的性质 → 6.3 证书是真正的 residual bearer
  → 6.4 法定到期检查与"什么条件下票据才会破"。

**一处必须改口径（原表述会被 §6 的 IRR 表当场打脸）**：
不能说"票据的真实风险是期限（赎回权），不是信用"，因为按面值赎回时 A-4 的 IRR 在行使与不行使之间只差
**0.24 bp**（5.3084% vs 5.3108%）。正确表述是：**赎回权带来的是期限与再投资风险，不是回报风险；
且方向是"不行使→延长到 4.18 年"，不是"行使→损失"。**
